# BIVAR v0.4 Progress Report

## Summary

**BIVAR v0.4 完成！** 6 个安全不变量规则，18/18 regression test，607 个真实候选。

## Rules

| Rule | Name | Type | Description |
|------|------|------|-------------|
| B001 | Addition Overflow | Arithmetic | `a + b > limit` 直接比较可能溢出 |
| B002 | Subtraction Underflow | Arithmetic | `a - b > limit` 没有 `a < b` 前置检查 |
| B003 | Integer Truncation | Representation | 64-bit → 32-bit narrowing conversion |
| B012 | Check Order Violation | Memory Access | 内存访问在边界检查之前 |
| B013 | Derived Index | Memory Access | `array[idx + delta]` 没有 `idx + delta < Size()` 检查 |
| B014 | Shift Width Violation | Arithmetic | shift amount 可能超过 operand width |

## False-Positive Case Studies

### 1. NTFS B013: SAFE_BY_SENTINEL
- Pattern: `Extents[i + 1]` in loop
- Reason: loop breaks on `e.IsEmpty()`, so i never reaches last element
- Lesson: sentinel invariant protects derived index access

### 2. 7z B013: SAFE_BY_CONTAINER_RELATION
- Pattern: `NameOffsets[index + 1]` in GetPath(index)
- Reason: `NameOffsets.Size() == Files.Size() + 1`, caller checks `index < Files.Size()`
- Lesson: parallel-vector +1 invariant protects derived index access

### 3. VMDK B014: SAFE_BY_EXPLICIT_BOUNDS
- Pattern: `1 << (grainSize_Log + k_NumMidBits)`
- Reason: `grainSize_Log <= 21`, `k_NumMidBits = 9`, sum <= 30 < 64
- Lesson: explicit bounds check on shift amount protects shift width

## Key Insights

### BIVAR 已经从 pattern matcher 进化为 security invariant analyzer:
- **Syntactic pattern**: `array[idx + 1]` / `x << n`
- **Semantic analysis**: sentinel / container relation / explicit bounds
- **Classification**: VULNERABLE / SAFE_BY_SENTINEL / SAFE_BY_CONTAINER_RELATION / SAFE_BY_EXPLICIT_BOUNDS

### Security invariant taxonomy:
```
Arithmetic
   ├─ addition (B001)
   ├─ subtraction (B002)
   └─ shift width (B014)

Representation
   └─ narrowing conversion (B003)

Memory Access
   ├─ check ordering (B012)
   └─ derived index (B013)
```
